Revana — AI-Powered Review Intelligence for E-Commerce Sellers

Stop reading reviews. Start making decisions. · Claude API · Streamlit · Team Project (BANA 274, UC Irvine)

🔗 View on GitHub

Amazon sellers are flying blind. They spend hours per week reading reviews one by one, trying to spot patterns an AI can find in seconds. Existing tools return little more than a star rating — no insight into what to actually fix, what competitors do better, or what's driving returns. Meanwhile, competitor reviews sit on a goldmine of market data that most sellers never see. The result: sellers fix the wrong things, listings underperform, and competitors quietly take market share.

The Solution

Paste an Amazon product ID (ASIN), get a complete product strategy in about 90 seconds. Revana is the only tool we found that combines fake-review filtering, competitor gap analysis, and AI-generated listing copy in a single workflow, at a price point any individual seller could afford:

  • Fetch — the Rainforest API pulls live Amazon reviews legally, with no scraping
  • Filter — a 12-signal heuristic scorer removes fake and bot reviews before any AI sees them
  • Analyze — Claude reads the trusted reviews and extracts a structured strategy
  • Brief — complaint themes, buyer personas, risk alerts, and keyword opportunities
  • Compete — add a competitor's ASIN to get a full gap analysis and positioning read

This was a 4-person team project and the role split wasn't strictly siloed — I ended up working across two parts of the pipeline:

  • Fake-review filtering & sentiment trends (utils.py) — the trust-scoring logic that flags unreliable reviews before they reach the AI analysis step, and the sentiment trend tracking over time
  • Review fetching (rainforest.py) — improved the Rainforest API integration with multi-sort-order requests, pulling a larger and more varied set of reviews within the constraints of the free-tier API

How It Works

This is a real multi-stage AI pipeline, not a thin wrapper around a chat model:

  • Data Ingestion — user enters an ASIN, the Rainforest API fetches product metadata and reviews legally (no scraping, no ToS risk), returned as a pandas DataFrame
  • Preprocessing — utils.py scores each review 0–100 across 11 trust signals: verified purchase (+40), review length, posting clusters, linguistic patterns, and reviewer history
  • LLM Analysis — analyzer.py sends only the trusted reviews to Claude Sonnet via the Anthropic API, in two separate calls: one for structured product analysis, one for competitor gap analysis
  • Output Layer — app.py renders an 8-tab Streamlit dashboard with Plotly charts, and exports to TXT, CSV, and JSON, with a demo mode for offline presentations
Technical Deep Dive: Design Choices, Evaluation & Limitations

Two Deliberate Technical Choices

11-signal trust scorer. Existing tools rely on star ratings, which fake and incentivized reviews easily inflate. Each review is scored on signals like verified purchase (+40), review length over 200 words (+10), suspiciously short 5-star reviews (−30), and autogenerated-looking reviewer names (−15). A score of 50 or higher is treated as trusted; on average this removes about 25% of the noise per product before any AI analysis happens.

Structured prompt engineering. Rather than a conversational response, Claude is prompted as a senior e-commerce strategist and required to return a strict JSON schema — themes, personas, risks, and keyword opportunities — with retry logic if invalid JSON comes back, and a separate call for competitor gap analysis. This makes the output machine-readable and consistent run to run.

Evaluation

  • ~25% of reviews filtered out as untrustworthy on average per product
  • 90 seconds end-to-end for a full brief, from ASIN input to output
  • Manual baseline: roughly 5 hours to read 500 reviews by hand, versus under 2 minutes for the Revana equivalent

What worked well: the fake-review filter consistently removed 20–30% of unverified, very short, or burst-posted reviews; Claude produced coherent, actionable complaint themes that matched what a human analyst would flag; competitor gap analysis correctly surfaced cross-product strengths and weaknesses from review language.

Where it breaks: complaint-frequency percentages become statistically unreliable with small review samples — a theme mentioned in just a few reviews can look more significant than it is. Full reliability would need 50+ reviews per product, which requires a paid API tier rather than the free tier we used.

Limitations

  • Free Rainforest API tier returns only 8–10 reviews per call; statistical confidence needs 50+ (a $50/month paid tier returns 100 per call with pagination)
  • The fake-review filter relies on heuristics, not a labeled ground-truth dataset — estimated false-positive rate around 10% from manual spot-checking
  • English-language reviews only; non-English Amazon marketplaces aren't supported in the current version
  • At scale, cost runs about $0.003 per Claude analysis plus $0.05 per ASIN on the paid Rainforest tier — roughly $15/month per seller for daily analysis

Business Context

There are an estimated 9.7 million active Amazon sellers worldwide, and for comparison, PayPal paid $4B to acquire Honey — a tool that only finds coupons. We didn't find any existing tool that combines fake-review filtering, competitor gap analysis, and AI-generated listing copy in one workflow, which is the gap Revana targets.

Why This Project Matters

Revana is a working, deployed application with a real evaluation behind it — not just a notebook. It's a concrete example of putting an LLM inside a production-shaped pipeline: filtering untrustworthy input before the model ever sees it, constraining its output to a strict schema, and being upfront about where the system's numbers stop being reliable.
